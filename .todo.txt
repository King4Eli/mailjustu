## RBAC (super admin / domain admin / user) -- how it actually works
- There's no self-serve "first admin" signup. The seeded
  admin@mail.example.com super admin was created with a direct SQL insert
  (see .test.credentials.txt) since /api/admin/mailboxes itself requires
  an admin session -- chicken/egg for the very first one. Document (or
  script) this bootstrap step before handing this off to someone else.
- Only super admins can grant/revoke is_admin (PATCH
  /api/admin/mailboxes/:id) or create/delete domains. A domain admin
  cannot promote a co-admin on their own domain -- by design, to avoid an
  easy privilege-escalation loop, but worth revisiting if that's too
  restrictive in practice.
- Domain admins can still be deleted (including by themselves) with no
  "don't lock yourself out" guard.

## Cleanup / consistency, not urgent
- ./.env/mysql.env and the old dedicated-mysql setup are unused now that
  ./.env/api.env points at the shared global_mysql instance -- either
  delete mysql.env or decide it's the fallback for standalone (non-shared)
  deployments and document that split explicitly.
- ./volumes/postfix/mysql-virtual-*.cf and
  ./volumes/dovecot/conf.d/auth-sql.conf hardcode the global_mysql
  credentials (mysql: map files don't support env expansion) -- if you
  rotate mail_justu_password1, update both places plus ./.env/api.env.
- The 1024M fallback quota is hardcoded in both
  ./volumes/dovecot/conf.d/auth-sql.conf's query and quota.conf, and
  mirrored in ./.env/api.env's DEFAULT_MAILBOX_QUOTA_MB purely for the
  admin dashboard's display -- same "duplicated because config can't read
  env" situation as the DB credentials above. Keep all three in sync.
- shared-global-network is `external: true` -- this compose file will
  refuse to start on a machine that doesn't already have that network
  created by whatever else manages it. Not portable as-is.
- api/src/db.js's migrate() uses plain `ALTER TABLE ADD COLUMN` wrapped in
  a duplicate-column catch, not `ADD COLUMN IF NOT EXISTS` -- that syntax
  errored on this MySQL 8.0.46 instance. If you add more columns later,
  follow the same catch-ER_DUP_FIELDNAME pattern.
- No automated tests. Everything so far has been verified by hand
  (curl + a couple of throwaway Puppeteer scripts).

## Known limitations, probably fine to leave
- Webmail/admin sessions are an in-memory token->{email,password,role,
  domain} map in api/ (see api/src/middleware/auth.js) -- restarting the
  api container logs everyone out, and it doesn't scale past one api
  replica.
- No password reset / account self-service flow -- mailbox creation is
  admin-only via the dashboard or POST /api/admin/mailboxes.
- Aliases only forward to a mailbox on this server (virtual_aliases.
  destination must be a real local mailbox) -- no forwarding to external
  addresses. They're also locked to the owning mailbox's own domain (see
  README) -- that's intentional, not a bug.
- MAX_MAILBOXES_PER_DOMAIN / MAX_ALIASES_PER_MAILBOX / quota_mb (and their
  per-domain overrides, set via the admin Domains tab) are only checked
  when creating a new mailbox/alias -- lowering a limit doesn't
  retroactively remove anything already over it (storage quota is the
  exception: Dovecot enforces that live, so a mailbox already over a
  newly-lowered quota just can't accept new mail until it's under again).
- Custom IMAP folders (webUI's "New folder") have no count limit.
- File uploads: compose-time attachments work end to end (multer on the
  API, real MIME attachments via nodemailer, saved to Sent too). There's
  no size/type restriction beyond multer's 25 MB-per-file/10-files caps,
  and no per-mailbox aggregate attachment quota beyond the mailbox's
  overall storage quota. Receiving attachments works (parsed via
  mailparser, name+size shown) but there's no download endpoint yet.
- No per-mailbox storage USAGE reporting (quota is enforced, but nothing
  surfaces "X of Y MB used" in the admin dashboard) -- would need
  `doveadm quota get` piped through api/.
- Rspamd's {= env.X =} config templating only resolves a handful of names
  baked into its own default rspamd.conf; custom env vars silently fall
  back to defaults instead of erroring. See the comment in
  ./volumes/rspamd/local.d/worker-controller.inc. Hardcoded there instead.
